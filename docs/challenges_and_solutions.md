# Challenges and solutions

Real problems met while building AfriPulse, how each was diagnosed, and what now prevents
it from coming back. Each one was found by a test, a data check or a dashboard, not by luck.

## 1. A dbt test caught a bug in the synthetic data generator

- **Symptom:** the reconciliation test `assert_loyalty_balances_reconcile` failed for 97
  customers: points earned minus points redeemed did not match the balance held.
- **Root cause:** the generator stamped some reward redemptions *after* the customer's next
  purchase, so balances were computed in the wrong time order.
- **Fix:** generator v2 always places a redemption before the next purchase.
- **Prevention:** a Python invariant (balances in time order) blocks bad data before loading,
  a regression test plants the error to prove the invariant catches it, and `generator_version`
  is part of the fingerprint, so data generated by v1 is replaced automatically. The same rule is
  now checked in Python, dbt and Tableau, and shows 0 on the loyalty dashboard.

## 2. The IMF data server refused the pipeline (HTTP 403)

- **Symptom:** downloads worked in a browser but returned 403 Forbidden from Python.
- **Root cause:** the IMF's content delivery network blocks requests with a custom User-Agent
  header. The pipeline was identifying itself with one.
- **Fix:** use the HTTP library's default User-Agent for the IMF source.
- **Prevention:** the HTTP client never retries 403 or 404 (retrying cannot help and looks like
  abuse) and keeps the start of the response body in the error, including the CDN's reference
  number, so the next failure of this kind is diagnosed in seconds. Recorded as finding F-IMF-1.

## 3. Namibia disappeared from the data

- **Symptom:** one African country had no rows after reading a file with pandas.
- **Root cause:** Namibia's ISO2 code is `NA`, which pandas reads as a missing value by default.
- **Fix:** every file is read with `dtype=str` and `keep_default_na=False`; types are applied
  explicitly afterwards.
- **Prevention:** a reference list of the 54 African countries and a dbt test that all 54 are
  present. A missing country fails the build.

## 4. "Sub-Saharan Africa" is not Africa

- **Symptom:** regional totals did not match country sums.
- **Root cause:** source country lists mix in aggregates (regions, income groups); the World
  Bank's Sub-Saharan Africa region excludes six African countries; one region name has a
  trailing space.
- **Fix:** AfriPulse defines Africa itself: 54 countries in a reference file (ADR 0001), with
  African Union regions. Aggregates are rejected at validation.
- **Prevention:** a validation check blocks any code not in the reference list.

## 5. The dashboards showed no population for 2024

- **Symptom:** the population KPI for 2024 was blank in Tableau.
- **Root cause:** the UN marks 2024 and later as *projections*, and the reporting layer
  excluded all projections. But for population, the UN's current-year estimate is the best
  available figure.
- **Fix:** in dbt, UN WPP values are kept up to the current year; later years stay excluded as
  projections. Africa's 2024 population is now 1,513 million.
- **Prevention:** projections are labelled throughout (`is_projection`, `value_type`) and
  drawn differently in the dashboards. Rebuilt and tested: `dbt build` PASS=212, ERROR=0.

## 6. Installing Airflow failed on an Intel Mac

- **Symptom:** `pip install` tried to compile `libcst` and failed (it needs Rust).
- **Root cause:** Airflow's official constraints pin three packages that publish no ready-made
  wheel for Intel Macs on macOS 12.
- **Fix:** override those three pins with the newest versions that do have wheels, all within
  Airflow's own version requirements, and install with `--only-binary=:all:` so pip can never
  fall back to compiling.
- **Prevention:** the overrides are in the Makefile with a comment explaining how they were
  verified (`pip download --platform macosx_12_0_x86_64 --only-binary=:all:`). Airflow lives in
  its own virtual environment because its pins conflict with dbt's.

## 7. Dashboard numbers that looked right but were not

Each of these produced a plausible number on screen; each was caught by cross-checking.

| Symptom | Root cause | Fix |
|---|---|---|
| GDP KPI showed 27,088 bn | It summed every year | Year filter on every KPI sheet |
| Top-10 "most contested" chart listed the wrong countries | Tableau applies Top N filters *before* ordinary filters | Made the other filters context filters |
| A country's latest internet % showed about 2,200% | A FIXED level-of-detail value repeats on every year row; SUM added the copies | AVG instead of SUM |
| South Africa ranked top for "phones but no internet" despite 78% online | Mobile subscriptions count SIM cards; multi-SIM ownership exceeds 100 per 100 | Capped subscriptions at 100 |
| Mobile money failure rate 1.6%, configured 2% | Not a bug: purchase-linked merchant payments never fail (a consistency rule in the generator) | Documented; traced to the code |

## 8. Repository hygiene caught before it mattered

- Airflow's generated UI password file was untracked but not git-ignored; one `git add .` would
  have published it. Airflow's runtime folder is now ignored, except the DAGs.
- A screenshot renamed on macOS (case-insensitive) broke on GitHub (case-sensitive) until the
  rename was committed.
- A dbt fix had been applied locally but never committed; `git status` before the release found
  it, and it was tested and committed.

## Known limitations

- **Synthetic spend per member by country:** Egypt and Ghana out-spend South Africa although
  South Africa's income is higher. The likely cause is small random merchant pools per country:
  a few extra electronics shops (x6 basket) outweigh the income effect. A future generator
  version could assign merchant categories in fixed proportions per country.
- **Income-group history** starts with the first snapshot; earlier changes are not back-filled.
- **Alerts** are local (log file and macOS notification); production would use email or Slack.
- **CI** runs lint and unit tests; integration tests need a PostgreSQL service and run locally.
